* **LoRA (Low-Rank Adaptation):** This is a Parameter-Efficient Fine-Tuning (PEFT) method where the pretrained model's base weights are frozen, and weight updates are represented as the product of two small, low-rank matrices. Only these small matrices are trained, which significantly reduces the number of trainable parameters and saves storage space.
* **QLoRA (Quantized LoRA):** This builds on LoRA by first quantizing the base model's weights down to a lower precision (such as 4-bit) to save a substantial amount of GPU memory. Then, it applies LoRA training on top of the quantized base model, allowing even larger models to be fine-tuned on more modest hardware.

Think about how quantization affects the memory footprint of the base model before the low-rank adapters are even applied.

[user]: [glossary_agent]: These concepts connect as a hierarchy of techniques designed to make fine-tuning large language models more efficient:

* **PEFT** is the broad umbrella category for any technique that avoids full fine-tuning by modifying or training only a small fraction of a model's parameters.
* **LoRA** is a specific and popular method *under* the PEFT umbrella, which achieves parameter efficiency by freezing base weights and introducing low-rank trainable adapters.
* **Rank (LoRA $r$)** is a key hyperparameter within LoRA that dictates the size and expressive capacity of those low-rank matrices.
* **Quantization** is a memory-saving technique that reduces the bit-precision of the model weights (e.g., from 16-bit to 4-bit). When combined with LoRA, it creates **QLoRA**, enabling efficient training on smaller hardware.

Consider how each concept tackles a different bottleneck—either the number of parameters you train (PEFT/LoRA/Rank) or the memory required to hold the model weights in memory (Quantization). How do you think reducing the rank affects the trade-off between model capacity and memory usage?
